哪些图标可以管理？

OverflowBar 仅提供能够安全识别和排列的状态图标。受保护的 macOS 控件会被排除；如果无法可靠确定来源或稳定身份，图标也可能不可选。

可以先打开另一个带菜单栏图标的应用，再在设置中点击 Refresh Icons。兼容性取决于应用和系统版本，并非所有被刘海遮挡的图标都能管理。

新图标出现后会怎样？

启用 Hide selected icons 后，新发现且符合条件的图标会加入已保存的选择。如果首次使用时没有已验证的历史顺序，当前图标列表会作为基线。受保护或身份不稳定的图标不会被加入。

箭头或第二排不显示。

先在设置中刷新图标列表。若箭头仍不可用，选择 More → Reset Icon Selection，恢复受管理的图标。

部分 macOS Tahoe 系统可能在控制中心的受保护状态中保留旧的图标归属信息。报告问题时请注明 macOS 和 OverflowBar 版本。反复重置控制中心或修改受保护的系统偏好设置，不是受支持的恢复方法。

为什么看不到实时预览？

屏幕录制权限是可选的。未授权时会使用可用的应用图标；如需实时预览，请在系统设置的“屏幕与系统音频录制”中启用 OverflowBar，并按系统要求退出和重新打开。

授予权限也不代表所有应用的图标都能被捕获。查看权限设置步骤。

点击图标，没有打开预期菜单。

刷新列表后重试。OverflowBar 会先检查源控件；如果不能确认激活结果，会让图标保持可访问，而不是反复尝试不确定的点击。

Cancel 可取消正在进行的布局操作。Retry Hiding 会先显示当前布局，再重新应用已保存的选择；如需重新开始，可使用 Reset Icon Selection。

如何恢复所有图标？

  • 关闭 Hide selected icons，显示受管理的图标。
  • 选择 More → Reset Icon Selection 并确认，恢复图标并清除选择。
  • 退出 OverflowBar，恢复图标并保留下次启动要使用的选择。

卸载时先退出应用，再从“应用程序”文件夹移除。

权限看起来已开启，却无法使用。

替换临时签名的本地构建后，旧权限可能仍关联旧签名。退出应用，在受影响的权限列表中仅移除失效的 OverflowBar 条目，重新添加 /Applications/OverflowBar.app、启用权限，再打开应用。

此方法用于替换构建后权限失效的情况。阅读完整权限文档。

首次启动被 macOS 阻止。

社区构建尚未公证。请从官方发布页下载，并按安装说明与 Apple 的“仍要打开”指引处理你信任的副本。

支持 macOS 27 吗？

当前引擎在 macOS 27 及以上版本禁用原生图标管理，并让图标保留在菜单栏中供访问。该兼容路径来自源码审查，macOS 27 的实际运行行为尚未验证。

macOS 15、26 和 Intel 呢？

应用包含通用二进制，最低部署目标为 macOS 15，已在 macOS 26.4 检查有限流程。macOS 15 和 Intel 实体机、完整显示器组合及第三方应用覆盖仍不充分。查看兼容性表。

会上传我的屏幕内容吗？

不会。预览捕获、菜单内容和图标选择保留在本机。更新器会连接已配置的 GitHub 发布源检查签名更新，并在安装前征求同意。阅读隐私说明。

免费且开源吗？

是的。OverflowBar 以 GPL-3.0 开源，原生引擎包含 Ice 和 Thaw 的贡献。这两个项目同样提供菜单栏管理和独立图标栏；OverflowBar 专注于选择图标，并通过第二排使用原有控件。

图标搜索、已保存的可见性配置和全局切换快捷键属于可能的后续工作，尚不是当前功能。
